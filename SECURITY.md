# Security and responsible reporting

**Status:** research documents and an educational, non-financial Python accounting example only. No ORD token, wallet, exchange, custody arrangement, API, blockchain, server, deposit address or live asset exists.

## What to report

Report flaws that could mislead readers about custody/backing, hide duplicate liabilities, compromise contributor privacy, or make the example code unsafe if copied into other contexts. An accounting demonstration passing its own tests is not proof of real asset security.

For safe-to-publish corrections, open a GitHub issue or pull request. **Do not post private keys, addresses of real individuals, account credentials, personal records or exploit details involving a real third-party service.** For an active GitHub platform issue or abuse, use GitHub's reporting mechanisms. If GitHub private vulnerability reporting is made available on this repository, use that channel for genuinely sensitive findings.

## Scope limits

There is no production system to patch or bounty to claim. No member is authorised to receive physical metal or money on the project's behalf. The project does not promise response times, an always-on operations team, or independent incident coordination while community maintainers are still being recruited.

An independent steward group should later publish a verified, confidential and jointly administered security contact; do not route sensitive reports through a founder's personal inbox by default.
